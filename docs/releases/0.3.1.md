# Hopper 0.3.1

Fix CurseForge credentials in managed instances and automatically elevate system
commands through sudo.

- Exporting a replacement `CURSEFORGE_API_KEY` refreshes the saved instance credential
  before install, repair, check, update, and configure. System workers receive the
  refreshed key through systemd credentials instead of continuing to use a stale key.
- CurseForge commands fail early when required credentials are missing or malformed.
  Explicit search reports a missing key instead of returning no results; configuration
  checks credentials before saving settings. Interactive configuration can use the
  saved instance key for version discovery.
- `--scope system` automatically elevates the coordinator through sudo before prompts
  or changes, preserving the CurseForge key. Root skips sudo. Noninteractive runs never
  prompt for a password and fail immediately if sudo authorization is unavailable.
  Pack workers continue to run unprivileged.

The release includes a statically linked Linux x86-64 binary and SHA256SUMS.
