# Hopper 0.3.3

Verified rolling world backups and automatic recovery for managed server updates.

- Back up the complete stopped instance before every changed update, including all
  worlds and dimensions, configs, mods, access lists, launcher, lock and managed Java
  runtimes. Verify archive contents and integrity before applying any files.
- Keep the latest two verified update backups by default. Configure retention with
  `hopper configure NAME --backup-keep N`; onboarding backups remain separate.
- Add `hopper backups NAME` and `hopper revert NAME [--backup ID]`. Revert restores
  the matching world and installation offline, pins the restored version where
  supported, and pauses scheduled updates while retaining restart schedules.
- Automatically revert failed applies and failed initial startups. Check authenticated
  RCON and Minecraft status for stable readiness, with a configurable 20-minute
  default timeout (`--startup-timeout SECONDS`). Stopped instances validate on their
  next `hopper start`; operator cancellation prevents automatic restart.
- Show conflict diffs and ask whether to keep local files or use incoming versions.
  Scheduled and noninteractive updates skip conflicting updates without stopping the
  current server. Recheck digest-bound choices after shutdown, and review acknowledged
  local edits again when upstream changes.
- Preserve recovery progress across interruptions. `hopper repair NAME` resumes
  restoration without registry access; incomplete recovery blocks ordinary starts.
- Include backup history, maintenance progress and outcomes in status and JSON output.

Reverting discards world progress made after the selected snapshot. Automatic recovery
covers the update and initial startup window; use manual revert for later problems.
Preflight checks require free space for a new backup, staged files and restoration.

Existing installations should run `hopper repair NAME` while stopped (add
`--scope system` for system instances) to refresh generated units and the system helper
before relying on scheduled recovery or startup guards.

The release includes a statically linked Linux x86-64 binary and SHA256SUMS.
